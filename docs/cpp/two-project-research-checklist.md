# 两个项目调研清单

记录日期：2026-07-03

## 用途

帮助我调研并筛选两个最适合的开源项目。

目标不是制定长期学习路线，而是尽快锁定：

- 2 个项目
- 1 条求职主线
- 1 套面试导向的准备范围

## 我的当前情况

### 已有能力

- 具备 `C++` 基本语法，掌握C++ 11，了解C++ 17，正在通过 `Xyce` 学大型工程
- 做过设计自动化方向研究
- 会一定的 `Python` / 机器学习
- 能接受阅读中大型开源工程并做整理、追踪、验证

### 当前短板

- 模拟电路基础还处于初学者阶段
- 不适合把求职完全押在“资深 SPICE / AMS / 模拟设计”这类强领域门槛方向
- 不希望走一条需要长期深挖极窄 EDA 子方向才能投递的路线

## 我想找的方向

优先考虑：

- 泛 EDA 行业的 `C++` 研发岗位
- EDA / CAD / 仿真 / 建模 / 特征提取 / characterization / 基础设施相关岗位
- 对应届生相对友好，允许用项目证明能力的岗位

希望覆盖的能力标签：

- `C++`
- Linux
- 工程代码阅读与调试
- 数据结构与软件设计
- 自动化脚本
- 基本数值 / 仿真直觉

不希望过度依赖的标签：

- 深模拟电路设计经验
- 多年 tapeout 经验
- 纯客户支持型岗位
- 只能投非常窄的 `SPICE` 内核岗位

## 需要筛选的两个项目

## 项目 A：SPICE 仿真器方向，偏高性能计算

### 定位

这个项目要保留一定的 `SPICE / 仿真器 / 数值求解` 特征，但重点不是器件物理深挖，而是：

- 大型 `C++` 工程
- 求解流程
- 性能
- 并行 / 批处理 / 数据规模
- 验证方法

### 这个项目最好体现的关键词

- `SPICE simulator`
- `solver`
- `transient / DC / Newton`
- sparse matrix / linear solve
- performance profiling
- parallelism / multi-thread / HPC awareness
- regression / correctness validation

### 这个项目最好解决的问题

- 读懂一条仿真主链路
- 做一个受控修改或扩展
- 展示如何验证结果正确
- 展示如何分析性能瓶颈或吞吐问题

### 这个项目的理想成果

- 能在简历中体现“仿真器 + C++ + 性能/数值”能力
- 面试时能讲清楚工程结构、核心算法位置、验证方法和性能思路
- 即使不投纯 SPICE 内核岗，也能作为高技术含量项目展示

## 项目 B：更通用的 C++ 项目，但对 EDA 岗位依旧有用

### 定位

这个项目需要明显降低“过窄 EDA 领域绑定”。

它不必继续深绑 `SPICE` 或仿真器主题，而应该是一个更通用的 `C++` 项目，只是它训练出来的能力，依旧能被 EDA 岗位认可。

更直白地说：

- 项目 A 负责保留 EDA / 仿真器技术深度
- 项目 B 负责扩大岗位适配面

### 这个项目最好体现的关键词

- `C++` 工程能力
- 算法与数据结构
- parser / IR / data model / pipeline
- automation
- batch processing
- testing / debugging
- maintainability
- performance awareness
- optional: Python integration

### 这个项目可以落在的题材范围

- 通用 parser / IR / 静态分析工具
- 面向工程工作流的数据处理或任务编排框架
- 批处理 / 回归测试 / 结果对比工具
- 小型科学计算 / 数值计算 / 性能优化型项目
- 与 CAD / EDA 场景“能力相通”但题材更通用的 `C++` 工具项目


### 这个项目的理想成果

- 能在简历中体现“我不只会看 SPICE，我也能做更通用的工程型 `C++` 项目”
- 能覆盖更广的泛 EDA `C++` 岗位
- 也能覆盖一部分非 EDA 的通用 `C++` / 基础设施 / 工程平台岗位
- 即使面试官不懂电路细节，也能看懂项目价值

## 对这两个项目的共同要求

- 对应届生可落地，周期不要过长
- 最好能在 1 到 2 个月内做出第一版可展示成果
- 需要有明确输入、处理流程、输出和验证方式
- 最好能保留一部分与 `Xyce` 或仿真工作流的联系
- 项目难度要足够体现技术含量，但不能依赖太多前置模拟设计经验
- 最终要能服务面试，而不是只服务学习兴趣
- 两个项目之间最好形成互补，而不是题材重复

## 输出格式要求

希望调研结果尽量简洁，最好每个候选项目都给出：

- 项目名称
- 项目目标
- 为什么适合我
- 对应岗位类型
- 需要的核心技术
- 最小可交付版本
- 风险点

如果是项目 B，最好额外说明：

- 它为什么足够通用
- 它为什么依然能被 EDA 岗位认可

## 最终目标

我不需要一份“大而全学习路线”。

我只需要：

- 两个足够强的项目
- 通过这两个项目吃透面试里会被追问的问题
- 让自己既能沾到 EDA 仿真器的技术深度，又不被过窄方向锁死
- 让第二个项目在必要时还能帮我扩展到更通用的 `C++` 求职市场
