# 求职导向学习路线

这份路线面向当前的目标组合：

- 主线：`SPICE / AMS / EDA 仿真器`
- 第一备线：`HPC / 科学计算 / CAE 仿真软件`
- 第二备线：`EDA 自动化 / 模拟方法学 / AI for EDA`

目标不是同时押三个完全不同的方向，而是先建立一套可复用的核心能力，再按岗位做轻微偏转。

## 总体原则

优先积累这四类通用能力：

- `C++`：中大型工程阅读、类与对象生命周期、容器、模板基础、调试
- 数值与仿真：矩阵、非线性求解、时间积分、收敛、性能
- 自动化：`Python`、批量实验、数据分析、参数扫描、结果对比
- 表达与验证：能讲清流程、能做小修改、能证明结果正确

## 第一阶段：打牢 C++ 与 Xyce 阅读能力

阶段目标：

- 能稳定阅读 Xyce 里的主要类和调用链
- 能理解构造、析构、所有权、命名空间、头文件组织
- 能从入口一路追到 netlist 解析、器件建模、求解流程

建议重点：

- 完成 `docs/cpp/` 下已有语法笔记
- 持续补“构造函数、析构函数、裸指针、容器中的指针、成员初始化列表”
- 练习回答四个问题：谁创建对象、谁持有对象、谁调用它、它影响什么

阶段产出：

- 一份 Xyce 启动流程图
- 一份 netlist 到矩阵装配的追踪笔记
- 一份常见 C++ 结构与 Xyce 实例对应表

## 第二阶段：主攻 SPICE / AMS / EDA 仿真器

阶段目标：

- 建立“仿真器不是黑盒”的理解
- 能解释一个电路仿真器的核心链路
- 能做小范围源码修改并验证

建议重点：

- SPICE netlist 解析与电路对象构建
- 器件实例化、参数保存、stamp/load 路径
- 直流工作点、瞬态分析、Newton 迭代、线性求解接口
- 收敛问题、调试思路、日志与结果核对

阶段产出：

- 追踪一个简单器件的完整链路，例如电阻
- 写一份“`parse -> instantiate -> load -> solve`”总结
- 做一个小改动并记录验证方法

## 第三阶段：扩展到 HPC / 科学计算 / CAE 仿真软件

阶段目标：

- 把“电路仿真器理解”扩展成“通用科学计算软件理解”
- 形成可以迁移到 HPC/CAE 岗位的话语体系

建议重点：

- 稀疏矩阵与线性系统基本概念
- 非线性求解、时间积分、数值稳定性
- 性能瓶颈分析、内存访问、批量实验与 profiling
- 并行与大规模计算的基本术语：任务划分、通信、可扩展性

阶段产出：

- 一份“Xyce 中哪些部分体现了科学计算软件共性”的笔记
- 一份从 EDA 仿真器迁移到 HPC/CAE 的能力映射表
- 至少一次性能或数据规模相关的小实验

## 第四阶段：补齐 EDA 自动化 / 模拟方法学 / AI for EDA

阶段目标：

- 把你已有的模拟设计背景和软件能力真正连起来
- 让自己不仅能读仿真器，也能搭建自动化设计与验证流程

建议重点：

- `Python` 自动化：批量仿真、结果解析、参数扫描、回归验证
- 模拟方法学：corner、Monte Carlo、yield、敏感度、约束管理
- AI for EDA：代理模型、参数优化、设计空间探索、实验管理
- Verilog-A 或行为模型的基础理解

阶段产出：

- 一个自动化实验脚本或小工具
- 一份“模拟设计问题如何转化为算法与自动化问题”的总结
- 一份适合简历展示的小项目说明

## 简历与面试表达重点

准备求职时，尽量把自己表达成：

“能够把模拟电路问题转化为建模、仿真、优化和软件系统问题的工程师。”

重点讲清这几件事：

- 你如何阅读和拆解中大型 C++ 工程
- 你如何追踪仿真流程和对象关系
- 你如何验证一个修改是否正确
- 你如何把设计问题自动化、数据化、算法化

## 一个简化的执行顺序

1. 先把 `Xyce + C++` 主线读通。
2. 再补数值求解与性能分析，向 `HPC / CAE` 扩展。
3. 同时用 `Python + 自动化` 把模拟设计背景连接进来。
4. 最后把成果整理成项目笔记、代码修改记录和简历表述。

## 当前最值得优先做的事

- 持续整理 `docs/cpp/`，把语法学习和源码理解绑在一起
- 至少完整追踪一个器件和一种分析流程
- 写一个最小自动化脚本，开始把“读代码”变成“做实验”
- 在学习过程中同步积累可展示的文档和结论

## 如果求职重点转向 C++ 岗位

记录日期：2026-07-03

如果接下来的目标从“SPICE/仿真器专门岗”收缩成：

```text
以 C++ 为主，
优先找泛 EDA 行业的软件研发 / CAD / 应用支持 / 算法工程岗位
```

那么当前这个 `Xyce` 学习项目最值得保留的，不是“我要把整个仿真器完全学完”，而是把它当成一个高质量的大型工程样本，用来训练下面这些真正可迁移的能力。

### 1. 大型 C++ 工程阅读与定位能力

这是当前最值得优先抓住的主能力。

对泛 EDA `C++` 岗来说，很多岗位不要求你已经写过完整仿真器，但会非常看重：

- 你能不能进入一个历史很长的代码库
- 你能不能看懂对象关系和调用链
- 你能不能在多 package、多层抽象里定位问题
- 你能不能在不破坏系统边界的前提下做修改

`Xyce` 恰好非常适合练这个能力，因为它天然包含：

- 多 package 分层
- `Manager / Factory / register`
- 抽象接口与具体实现
- 比较典型的旧式 `C++` 工程组织方式

所以从求职角度看，`Xyce` 对你的第一价值不是“电路仿真”，而是：

```text
它是一个很像真实工业 EDA 软件的大型 C++ 工程训练场。
```

### 2. 数据模型和处理流水线意识

泛 EDA 岗位非常常见的一类工作，其实不是“手写 solver”，而是做这类事情：

- 输入格式解析
- 内部数据模型组织
- 规则/约束传递
- 中间结果缓存
- 结果导出、比对、验证

在 `Xyce` 里，这些可以通过下面的主线来训练：

- `netlist -> parser -> 电路对象`
- `器件/模型 -> instance -> assembly`
- `analysis setup -> solver -> output`

这条链路特别值得注意，因为它本质上和很多泛 EDA 工具都相通：

- 前端读入设计/约束
- 中间层建立内部表示
- 核心引擎做计算或变换
- 后处理输出结果

如果你以后投的是 STA、characterization、physical design、验证基础设施、建模平台、CAD 自动化这类岗位，这种“pipeline 思维”会很有用。

### 3. 调试、验证和可证伪习惯

EDA 软件岗位非常怕一种候选人：

- 只会讲思路
- 不会验证
- 结果不对时没有排查顺序

而 `Xyce` 项目很适合培养一个非常值钱的习惯：

- 做修改前先说清改哪一层
- 修改后用最小样例验证
- 波形不对时先怀疑输入、模型、数值、代码哪一层出问题
- 把“为什么认为它正确”讲清楚

这类能力在很多泛 EDA `C++` 岗里都比“背很多算法名词”更有区分度。

### 4. 数值与工程直觉的最低可用层

你现在是模拟电路初学者，这没有关系，但要注意一个边界：

- 你不需要短期内变成资深模拟设计工程师
- 但你需要达到“不会把仿真和建模问题讲错”的程度

对 `Xyce` 项目来说，最值得掌握的不是器件物理最深处，而是下面这一层：

- `KCL / MNA` 的基本含义
- residual / Jacobian 是什么
- Newton 为什么会出现
- transient 为什么要做时间离散
- 为什么会有收敛、步长、误差控制这些问题

这层一旦稳住，你以后不管投仿真、建模、characterization、优化、验证基础设施，都会更有底气。

### 5. 自动化和实验平台能力

你做过设计自动化研究，这其实是很强的可迁移资产。

比起把自己包装成“模拟电路新人”，更好的表达方式是：

```text
我能把工程问题组织成可重复实验、可批处理流程、
可分析数据和可验证修改。
```

所以当前项目里特别值得补的一块不是继续纯读文档，而是尽快加上：

- 小型批量仿真脚本
- 参数扫描
- 结果提取与对比
- 回归验证
- 失败 case 的保存与复现

这会让你从“会读代码的人”升级成“能搭实验闭环的人”。

### 6. 机器学习背景要作为加分项，不要反客为主

你“懂一点机器学习”是加分项，但现阶段不建议把主线改成 `AI for EDA`。

更稳妥的做法是：

- 主线仍然是 `C++ + EDA 工程 + 自动化`
- 把 `ML` 放在“可迁移能力”位置

也就是以后可以这样讲：

- 我理解实验管理、特征、优化和代理模型的基本思想
- 我能把它们用在参数搜索、结果分类、异常检测、性能建模上
- 但我当前的核心价值仍然是能进入真实 EDA 工程代码和流程

这种讲法会比“我会一点机器学习，所以想做 EDA+AI”更扎实。

## 结合当前基础，最值得押注的岗位画像

如果以你现在的起点来选，优先级更建议是：

1. 泛 EDA `C++` 研发岗
2. EDA/CAD 自动化与基础设施岗
3. 仿真相关应用工程或方法学支持岗
4. 更硬核的仿真器内核研发岗

原因不是你做不到第 4 类，而是：

- 第 1 到第 3 类更容易用你已有的自动化研究背景建立可信度
- 它们同样认可 `C++ + Python + Linux + 工程调试 + 数据流程`
- 对模拟电路“深设计经验”的硬性要求通常更低

## 当前项目里最值得优先做成作品的 4 件事

### 1. 一张大型工程地图

目标不是画得漂亮，而是能说明：

- 入口在哪里
- 哪些 package 负责什么
- 哪些类负责调度
- 数据如何从输入流到输出

### 2. 一条完整调用链追踪

建议至少做一条：

- `main -> Simulator -> analysis selection -> solver`

或者：

- `netlist -> parser -> device instance -> load/stamp`

这类材料非常适合面试时讲“我是怎么进入陌生代码库并搞清主路径的”。

### 3. 一个最小自动化实验

例如：

- 批量运行若干 netlist
- 自动提取关键结果
- 比较修改前后差异
- 形成一个最小回归脚本

这会直接体现你做过设计自动化研究的优势。

### 4. 一次受控修改与验证记录

哪怕只是很小的修改也可以，关键是要能写清：

- 为什么改这里
- 改动影响哪一层
- 如何验证没有引入明显回归
- 如果结果异常，你是怎么排查的

## 当前不值得过度投入的方向

如果目标是尽快让项目服务于求职，下面这些内容可以先降低优先级：

- 过深的 compact model 物理细节
- 很后面的 `HB / MPDE` 特殊分析
- 为了“学全”而扫完整个源码树
- 过早把重心切到 `AI for EDA`

这些都不是没价值，而是当前边际收益不如：

- `C++` 工程阅读
- 自动化实验
- 验证与调试
- 可讲清的项目产出

## 一句更适合你的定位

比起把自己定位成：

- “模拟电路初学者，正在学仿真器”

更建议把自己定位成：

- “具备设计自动化研究背景，正在用 `Xyce` 系统补齐 EDA 软件、数值仿真和大型 `C++` 工程能力的人”

这个定位更接近你真正的优势组合，也更适合投泛 EDA `C++` 岗。
