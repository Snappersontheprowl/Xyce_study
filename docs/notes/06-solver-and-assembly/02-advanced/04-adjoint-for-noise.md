# adjoint for noise

记录日期：2026-06-06

## 这篇的定位

这一篇不是一篇完整的伴随法总论。  
它只回答当前 `NOISE` 主线里最关键的一个问题：

```text
为什么 Xyce 在 NOISE 分析里要做 adjoint solve，
而不是对每个噪声源都单独做一次正向求解？
```

所以这篇的深度只服务当前主线，不扩展到更一般的灵敏度分析或优化理论。

## 当前结论先写在前面

`adjoint` 在 `NOISE` 里最值得先记住的一句话是：

```text
如果输出观测量已经固定，
那么一次 adjoint solve 就能把“输出对整个线性系统的灵敏度”算出来，
后面很多器件噪声源都可以直接投影到这份灵敏度上，
不必为每个噪声源都重新做一次正向求解。
```

这就是它在工程上最直接的价值。

## 第一步：如果不用 adjoint，会发生什么

先把 `NOISE` 当前频点下的小信号线性系统记成：

$$
A(\omega)x = b
$$

这里你可以先把：

$$
A(\omega) = G + j\omega C
$$

看成当前频点下已经组装好的线性系统矩阵。

现在假设我们要研究很多器件噪声源：

- 第 1 个噪声源
- 第 2 个噪声源
- 第 3 个噪声源
- …

并且我们只关心一个固定输出量，比如：

- 某个输出节点电压
- 两个节点的电压差

如果不用 `adjoint`，最朴素的做法就是：

1. 把第 1 个噪声源当输入，解一次正向系统
2. 把第 2 个噪声源当输入，再解一次正向系统
3. 把第 3 个噪声源当输入，再解一次正向系统
4. …

这样每个噪声源都要做一次：

$$
A(\omega)x_k = b_k
$$

如果噪声源很多，这个成本会很快变高。

所以这类问题的结构其实是：

```text
一个固定输出
+ 很多个不同输入源
```

这正是 `adjoint` 很适合出场的场景。

## 第二步：adjoint 的最小线性代数图像

先假设我们关心的输出量可以写成：

$$
y = c^T x
$$

这里：

- $x$ 是当前线性系统的解
- $c$ 是“怎么从全系统状态里取出输出量”的向量

而正向系统是：

$$
A x = b
$$

那么输出量也可以写成：

$$
y = c^T A^{-1} b
$$

这时定义一个新的向量 $\lambda$，让它满足：

$$
A^T \lambda = c
$$

那么就有：

$$
y = \lambda^T b
$$

这一步就是整个 `adjoint` 思想的最小核心。

它的意思是：

```text
先解一个“输出决定的转置系统”，
得到 λ；
以后任意输入 b 对这个输出的影响，
都可以通过 λ^T b 直接算出来。
```

这就是为什么 `adjoint` 很适合：

- 固定输出
- 很多不同输入源

的场景。

## 第三步：把这个图像翻译回 NOISE

在 `NOISE` 里：

- 固定的输出量
  - 通常是 `.NOISE` 指定的输出节点或节点差
- 很多不同输入源
  - 是各个器件内部的噪声源

所以 `NOISE` 面对的问题正好是：

```text
我只关心一个输出量，
但有很多噪声源都在往这个输出上“贡献”。
```

这时用 `adjoint` 就很顺：

1. 先针对这个固定输出量建立一个 adjoint RHS
2. 解一次转置线性系统
3. 得到输出对全系统的灵敏度
4. 再让每个器件噪声源投影到这个灵敏度上

所以从概念上最值得先抓住的一句是：

```text
NOISE 里的 adjoint，
本质上是在先求“输出怎么看整个系统”，
然后再让每个噪声源去碰这个“看法”。
```

## 第四步：为什么代码里会出现 solveTranspose()

上面的线性代数里，adjoint 的核心方程就是：

$$
A^T \lambda = c
$$

所以到了代码里，一个非常自然的落地点就是：

- 解转置系统

这正对应：

- [N_ANP_NOISE.C](../../../vendor/Xyce-7.10.0/src/AnalysisPKG/N_ANP_NOISE.C)
  里的 `solveAdjointNOISE_()`

这里最关键的一句就是：

```cpp
blockSolver_->solveTranspose();
```

这不是“另一套神秘求解器”，而就是上面这条方程的代码落地：

$$
A^T \lambda = c
$$

其中：

- `A` 是当前频点下的 block AC/NOISE 线性系统
- `c` 是由输出观测量构造出来的 RHS

所以这一句最该先理解成：

```text
现在不是在重新求一个正向 AC 解，
而是在求“输出观测量对应的转置系统解”。
```

## 第五步：output vector 是怎么变成 adjoint RHS 的

再看：

- `setupAdjointRHS_()`

这里做的事情，本质上就是把：

```text
我关心哪个输出量
```

翻译成线性代数里的那个 $c$。

在代码里你会看到：

- 对输出节点对应的 GID 放 `+1`
- 如果是差分输出，另一端放 `-1`

这其实就是在构造：

$$
y = c^T x
$$

里的 `c`。

所以这里最该先记住的是：

```text
adjoint RHS 不是新的物理激励源，
而是“输出观测量”的代数编码。
```

## 第六步：器件噪声源是怎么接到 adjoint 解上的

再看：

- `loader_.getNoiseSources(noiseDataVec_);`

这一步会让器件层把各自噪声源的信息填进 `noiseDataVec_`，包括：

- 噪声谱密度
- 噪声源连接在哪些节点之间
- 是否有相关项

然后在 `solveAdjointNOISE_()` 里，会把当前的 adjoint 解拆成：

- `Xreal`
- `Ximag`

再按噪声源的节点位置去取：

- `li_Pos`
- `li_Neg`
- `li_PosCorl`
- `li_NegCorl`

从而形成每个噪声源对输出的 `gain`。

这一步的本质就是：

```text
用 adjoint 解提供的“输出灵敏度”，
去评估每个噪声源对输出的投影大小。
```

也正因为如此，后面才会有：

- `outputNoiseDens`
- `inputNoiseDens`

这些量。

## 第七步：为什么它比“逐源正向求解”省

现在就可以把工程收益说清楚了。

如果没有 `adjoint`：

- 每个噪声源都要单独求一次正向响应

如果用了 `adjoint`：

- 固定输出量时，只要解一次转置系统
- 后面的许多噪声源只做投影计算

所以当“源很多、输出少”时，`adjoint` 特别划算。

而 `NOISE` 恰恰就是这种结构：

```text
器件噪声源很多
输出观测量通常很少
```

所以在这个问题里，`adjoint` 不是数学炫技，而是非常实际的算法选择。
